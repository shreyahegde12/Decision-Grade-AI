How it works

Model advises. Policy decides.
Evidence is re-verified.

An LLM's confidence is not evidence. TrustGate treats all model output as untrusted: every extracted claim must quote the source text verbatim, every verdict is bound to the exact bytes of the diff it authorizes, and every unknown fails closed.

Fail closed

Missing, stale, failed, or unverifiable results deny by default. NOT VERIFIED never grants permission.

02

Exact-content binding

An approval fingerprints repo, base, head, and the exact diff. A different change needs a new review.

03

Role separation

Developers submit; reviewers resolve. Reviewer approval is risk acceptance — it never inflates the evidence score.

Integrations

Built on the challenge stack

Three layers, one job: turn AI output into a decision you can defend.

Ezio the input — reports under review

Ezio (ezioai.io) generates the research reports TrustGate judges. Reports are exported as PDF or text and imported through the extension (pypdf extracts PDF text locally) or pasted into the dashboard. The user states who relies on the answer and for what — that context determines which claims are material. Because Ezio exposes no authenticated verification API, provenance is explicit: imported reports are labeled user-supplied, and a report approval authorizes only that stated use — never an unrelated code push.

HarnessRouter the analyzer — advisory only

HarnessRouter runs the LLM analysis through a configured review harness at api.harnessrouter.ai/{harness_id}/v1/responses (or Community Edition via HR_MODE=ce). The prompt instructs a read-only harness to treat input as untrusted data and return strict JSON: 0–5 scores for accuracy, bias, tone and agreement; claims with verdicts, verbatim quotes and real sources; findings with severity; and a coverage flag. Output is then re-validated quote-by-quote against the source — the harness advises, the policy decides.

TokenRouter the routing & credential layer

Every request moves through a token-routed boundary. Provider calls carry HR_API_KEY bearer auth and a per-request Idempotency-Key through a single configurable endpoint (HR_BASE_URL) — credentials stay server-side and never reach the extension or dashboard. On the user side, separate developer and reviewer tokens route to different roles and permissions: developers create reviews; only reviewers can resolve escalations — with a written reason, inside a 15-minute window.

Enforcement

A gate that actually gates

Most trust tools build dashboards that report risk. TrustGate ships a Git pre-push hook that stops it: every ref update recomputes the approval fingerprint server-side, and anything stale, changed, or unreviewed is denied.

🔏

Byte-exact approvals

SHA-256 over repo identity, base, head, scope, and the exact diff. Approve one change — it can never authorize a different one.

⏱

15-minute expiry

Approvals decay fast. Push late and the gate re-checks — new evidence always requires a new review.

🚫

Deny by default

Tags, deletes, missing objects, backend failures, malformed responses — all denied in v1. Multi-ref pushes need per-ref approvals.

🧭

Honest limits

A local hook is bypassable by its owner — documented as a local guard, with org-level protected-branch checks as the rollout target.

Under the hood

Zero dependencies. Everything auditable.

The entire backend is Node 24 built-ins — node:http for the authenticated API and node:sqlite (WAL, foreign keys) for the durable review queue and audit trail. No npm install, no supply chain.

editor

VSIX extension

One editor-neutral package on the stable VS Code API — installs in VS Code, Cursor, Windsurf. Nonce-CSP webview, token in SecretStorage.

dashboard

Browser console

Same-origin only, tokens in tab memory, evidence inspector plus reviewer resolution — no editor required.

cli

Git pre-push gate

Reads every ref update from stdin, recomputes fingerprints, fails closed. Hook installer refuses to clobber existing hooks.

engine

Deterministic policy

Quote-grounded evidence validation, verdict mapping, expiry and role checks — the same code path for reports and code.
